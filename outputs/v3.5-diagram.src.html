一次请求怎样穿过前端、后端、Redis 和 PostgreSQL

后端先查 Redis：命中就直接返回，未命中才查 PostgreSQL。所以响应快不快，主要看缓存命中率。

拓扑：谁调用谁

浏览器里的前端只和后端通信；数据层的两个存储都只有后端能访问。蓝色粗箭头是热路径（缓存命中），橙色是 HTTP 请求。

从到动作
Frontend（React SPA）BackendHTTPS / JSON 请求
BackendRedisGET，命中直接返回（热路径）
BackendPostgreSQL未命中时执行 SQL，再回填缓存
BackendFrontend返回响应

为什么命中率决定延迟

假设 Redis 一次读取约 1 ms、PostgreSQL 查询约 10 ms（示意值）：命中率 90% 时平均约 1.9 ms，命中率 50% 时约 5.5 ms。命中率每降一点，就有更多请求走慢路径。

边界条件：缓存失效瞬间大量请求同时未命中，会一起压到 PostgreSQL（缓存击穿），需要加锁或提前刷新。
